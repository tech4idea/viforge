ViForge / Agent Harness

RuntimeConfig 从历史配置入口到发布审计的完整交互逻辑

这是单机版自用 Harness。用户围绕“运行配置”完成一次可验证的配置变更：选择或生成评测案例来固定对话开始前的上下文环境，编辑 Agent 提示词、工具说明和行为规则，选择评测运行策略、断言配置和人工审阅模板，执行隔离评测，完成人工审阅，最后发布、强制发布、回滚或归档。草稿和候选配置始终不影响普通运行。

目标用户
本机用户本人：自己配置、自己评测、自己审阅、自己发布
主要对象
运行配置、评测案例、评测运行、人工审阅、发布记录
默认产品调性
本地工作台 UI，强调可扫读、可追溯、可防错
交付形态
静态 HTML 交互逻辑稿，可直接浏览

范围与设计原则

界面必须让用户只理解“运行配置是发布和生效单位”。本系统是单机版本，不做多人角色、审批流或权限分工；所有审计记录都服务于用户自己的复盘、回滚和风险确认。

新建流程表单

点击新建后进入独立流程页，先选择产品和目标范围，默认复制当前 active 作为基线，自动命名为“产品 / 范围 / 时间”。此时只是未保存表单。

保存草稿

保存草稿只记录流程壳和当前节点输入。没有真实 Agent 配置差异时，不生成候选运行配置，也不显示“创建成功”的配置版本提示。

重测标记

候选已经产生 EvalRun 后再次修改 Agent 配置，已有结果标记为“基于旧候选”，发布 Gate 不再使用这些旧结果作为通过证据。

单次配置路线图

路线图固定展示在单次配置页顶部，帮助用户判断当前处在哪一步、哪些步骤已阻塞、哪些证据还缺失。

  • 任一步产生影响配置的修改后，后续 EvalRun 和 Gate 状态标记为“需重新验证”。

步骤一：评测案例选择或生成

评测案例只负责构建对话开始前的上下文环境，不包含断言。断言统一放到步骤三配置，避免“案例断言”和“运行断言”两个概念重复。

默认 Repro可从失败运行生成

交互流程

历史消息失败运行手动创建待确认

用户动作

  1. 在路线图点击“评测案例”。
  2. 用同一个选择框选择历史案例上下文，或选择“新建案例上下文”。
  3. 选择历史项时直接加载为当前节点输入；选择新建时只生成未保存表单，不提示成功。
  4. 确认对话开始前的上下文：最近消息、工作区快照、固定 memory、固定 knowledge。
  5. 必要时裁剪上下文，去掉与复现无关的信息。
  6. 点击保存或下一步时校验上下文是否完整、引用是否有效，校验通过后才保存并加入本次评测范围。

系统规则

  • 从失败运行生成时，只用运行证据定位对话起点和上下文环境；文件 diff、工具事件可作为背景证据展示，但不变成断言。
  • 敏感上下文默认生成 excerpt + hash 或 summary + hash，避免把密钥、隐私和超长输出写入案例正文。
  • 评测案例上下文可以被其它流程复用。复用时记录来源案例名、来源流程和保存时间。
  • 案例保存后只进入案例库，不改变任何候选运行配置，也不携带断言配置。
  • 手动创建作为后续能力预留：用户可以手写起点消息并上传或选择工作区上下文，但第一版主路径仍以历史对话为主。

步骤二：Agent 配置

该步骤集中处理提示词、工具说明和行为规则。每个配置项都支持用户自定义命名，或使用“产品 / agent / 片段类型 / 时间”的自动命名，便于在后续流程中复用。

页面布局

左侧配置目录

  • Agent 提示词：按 agent 列表选择，支持 active/candidate diff。
  • 行为规则：新增、编辑、停用，标注 system/product/agent。
  • 工具说明：选择工具，编辑主描述、参数说明、输出说明。
  • 复用选择：从历史流程选择某个已命名 Agent 配置作为当前节点输入。
  • 暂不配置产物结构。涉及历史上下文和记忆重建，当前版本只展示为非本期范围。

保存与候选生成

  • 选择历史配置时直接复用为当前节点输入；选择新建时只打开表单，不写入候选。
  • 同一 Agent 配置允许同时存在多个原子变更项，页面按分区和条目逐条展示，但保存时仍只生成一个候选运行配置。
  • 保存前必须校验每条变更都有真实差异、名称可识别、生效范围合法、内容不为空；Harness 不做内容语义审查。
  • 保存或下一步校验通过后，系统创建或更新本次候选运行配置，并生成改动清单；改动清单按原子变更条目列出。
  • 改动清单字段：生效范围、改动类型、改动对象、来源版本、目标版本、摘要、风险等级、是否需要重新评测。
  • 同一节点配置可被其它流程复用。复用时记录来源流程、来源配置名、来源版本和应用时间。
  • 复用历史配置后修改，只会生成新的候选版本或新版本引用，不会回写原始配置版本。
  • Harness 只校验结构、引用和版本差异，不做行为规则或工具说明的内容语义审查。

发布决策区

普通发布Gate 全部通过后启用。发布后候选成为已发布运行配置，旧 active 归档。

状态机与异常处理

状态机必须同时覆盖配置状态、评测状态和发布记录，避免用户误以为草稿或候选已经影响普通运行。

草稿

可编辑，可删除；未被评测引用时允许硬删除。

候选

可评测，可审阅，可发布检查；不影响普通运行。

已发布

普通运行读取该配置；只读展示，可回滚到其它已发布版本。

已归档

保留审计链路和历史结果，不参与普通运行和默认选择。

重新评测提示

候选配置变更后，已有 EvalRun 标记为“基于旧候选”，发布 Gate 不再使用这些结果作为通过证据。

覆盖不足提示

agent 范围要求覆盖对应 agent 的案例上下文；product 范围要求覆盖核心 agent 流程；system 范围要求展示跨产品 smoke 缺口。

引用保护

评测、审阅或发布记录引用过的配置片段、案例和候选不可硬删除，只能归档。

节点选择框行为新建校验保存时机
评测案例上下文同一选择框列出历史案例上下文和“新建案例上下文...”必须有起点用户消息、上下文快照或手动上下文，引用关系合法点击保存或下一步后创建

评测运行配置同一选择框列出历史评测运行配置和“新建评测运行配置...”必须至少修改评测运行策略、断言配置或审阅模板中的一项点击保存或下一步后创建
断言配置同一选择框列出历史断言配置和“新建断言配置...”至少一条有效断言；路径、工具、diff 条件必须可执行点击保存或下一步后创建
审阅模板同一选择框列出历史审阅模板和“新建审阅模板...”至少一个打分项，总权重合法，决策选项完整点击保存或下一步后创建
